# Семейный офис: портфель российских акций

## Когда использовать
- «Мой портфель: SBER, LKOH, MGNT», «у меня 100 Сбера по 280», «купил / продал …», «что у меня в портфеле».
- «Что с портфелем сегодня?», «разбери торги по моим акциям», «почему упал Магнит?», «брифинг».
- «Недельный обзор», «как портфель против индекса», «не слишком ли много нефтянки».
- «Каждый день присылай брифинг», «по субботам — обзор» (расписание).
- «Разбери X комитетом», «стоит ли докупать X», «вышел отчёт X — что изменилось».

## Главная идея
1. **Команда, а не один голос.** Ежедневную работу ведёт семейный офис (`references/family-office.md`):
   CIO, трейдер, аналитики по бумагам, риск-менеджер, офицер корпоративных событий и дивидендов, макростратег,
   адвокат дьявола. Решения по отдельной бумаге принимает инвесткомитет (`references/expert-panel.md`).
2. **Память — в папках, а не в голове.** Корень `~/family-office/` (переменная `FAMILY_OFFICE`): `portfolio.json`,
   брифинги и обзоры в `_portfolio/`, по папке на каждую бумагу (`README.md`, `thesis.md`, `journal.md`,
   `analyses/`, `news/`, `reports/`, `market/`). Перед работой по бумаге прочитай её `thesis.md`, хвост `journal.md`
   и последний протокол. Структура — `references/desk-structure.md`.
3. **Только свежие данные с датой и источником.** Цены, ставки, отчёты, дивиденды — из первоисточника в момент
   работы, никогда из памяти модели.
4. **Хранилище — это Obsidian-вики.** Хаб `<ТИКЕР>/<ТИКЕР>.md` на каждую бумагу (вердикт, скоринг, оценка, ссылки
   на тезис, протоколы, конспекты отчётов), `index.md`, журнал знаний `log.md`, темы `topics/`, недельные дайджесты.
   Формат общий для всех агентов семейства — `references/wiki.md`; папки бумаг совместимы с ru-stocks-agent.
   **Личное (позиции, количества, средние цены, брифинги) в вики-заметки про бумаги не пишется**: только в
   `portfolio.json` и `_portfolio/` (они в `.gitignore` хранилища).
5. **Шум — не сигнал.** В тихий день брифинг занимает три строки. Существенное событие не пропускается никогда.

## Инструменты (`scripts/`, Python 3.9+, только stdlib; для PDF — `pypdf`)
| Скрипт | Что делает |
|---|---|
| `portfolio.py set/add/update/trade/remove/import/list` | Портфель в `portfolio.json`: список тикеров, по желанию количество, средняя цена, сектор, целевая доля (`SBER:100@285`). `trade X buy|sell КОЛ-ВО [ЦЕНА]` пересчитывает количество и среднюю. `import` — CSV брокера. Каждая бумага автоматически получает папку |
| `portfolio.py session [--save] [--alerts]` | Разбор последней торговой сессии: по каждой бумаге цена, день против IMOEX, гэп, оборот к среднему за 20 дней, положение закрытия в диапазоне, 5д/1м, 52 нед., 200-дн. средняя, движение в σ, доля и вклад, P&L, отсечки с последним днём покупки, состояние тезиса; сигналы ⚑; фон рынка (индексы и секторные индексы, юань, курсы ЦБ, Brent). `--save` → `_portfolio/daily/`, `history.csv`, цены в папки бумаг |
| `portfolio.py review [--save]` | Недельный обзор: доходность против IMOEX (неделя / месяц / 3 мес. / год / YTD), волатильность, бета, просадка, связанные пары, вклад бумаг, тезисы, отсечки |
| `portfolio.py log / path` | Хронология портфеля; где лежат файлы |
| `news.py [тикеры] [--days N] [--all]` | Новости из Google News RSS и своих RSS в `news/news.jsonl` бумаги без дублей; ⚑ — существенные по заголовку |
| `desk.py status/show/analysed/log/add/remove` | Папки бумаг: что изменилось с последнего разбора, хронология, запись итога комитета |
| `moex_share.py <тикер> [--save]` | Карточка бумаги: цена, капитализация, доходность против IMOEX, 52 нед., волатильность, дивиденды |
| `gir_bo.py <ИНН> [--save ТИКЕР]` | РСБУ из ГИР БО ФНС |
| `report_extract.py <URL/PDF> [--save ТИКЕР --name 2026-h1-ifrs]` | Текст и ключевые строки из PDF-отчёта, архив в `reports/` |
| `wiki.py init/sync/log/note/find/lint/digest` | База знаний Obsidian: хабы бумаг, конспекты отчётов, `index.md`, журнал знаний `log.md`, поиск по вики, проверка (битые ссылки, цифры без источника, устаревшие тезисы, противоречия), недельный дайджест. `desk.py` и `report_extract.py --save` обновляют вики сами |
| `valuation.py [--ticker X] ...` | Мультипликаторы, DCF в трёх сценариях, обратный DCF, модель Гордона |

Запуск: определи папку навыка (где лежит этот SKILL.md) и вызывай `python <папка_навыка>/scripts/portfolio.py ...`.
Типовые места: Hermes — `~/.hermes/skills/finance/ru-portfolio/` (Windows: `%LOCALAPPDATA%\hermes\skills\finance\ru-portfolio\`)
или `.../profiles/portfolio/skills/finance/ru-portfolio/`; OpenClaw — `~/.openclaw/skills/ru-portfolio/`; Claude Code — `~/.claude/skills/ru-portfolio/`.
В Windows, если `python` не найден, пробуй `py` или `python3`.

Справочники (в Hermes — `skill_view(ru-portfolio, <путь>)`):
- `references/family-office.md` — **семейный офис**: команда, ежедневный брифинг, недельный обзор, эскалация. Читать перед процедурами 2–3.
- `references/expert-panel.md` — **инвесткомитет** по бумаге: роли, порядок заседания, голосование. Читать перед процедурой 4.
- `references/report-template.md` — шаблоны брифинга, сообщения владельцу, недельного обзора, протокола комитета.
- `references/analysis-framework.md` — методология: бизнес, финансы, оценка, дивиденды, корпоративное управление в РФ, скоринг.
- `references/desk-structure.md` — что лежит в хранилище и как его вести.
- `references/wiki.md` — **база знаний**: формат Obsidian-вики, frontmatter, ссылки, источники, операции, общее хранилище агентов.
- `references/data-sources.md`, `reading-reports.md`, `news-forums.md` — где брать данные, как читать отчётность, как проверять новости.

## Процедуры

### 1. Состав портфеля («мой портфель…», «купил…», «продал…»)
1. Пользователь даёт список акций: `portfolio.py set SBER LKOH MGNT` (заменяет состав) или `portfolio.py add X`.
   Если он назвал количество и среднюю цену — `ТИКЕР:КОЛ-ВО@СРЕДНЯЯ` (`SBER:100@285,4`). Без них портфель считается
   равновзвешенным. Не требуй количество, если его не дали; можно один раз предложить.
   CSV брокера — `portfolio.py import file.csv`. Если выгрузка в XLSX, PDF или на скриншоте, прочитай её сам и собери строку для `set`.
2. Сделки со слов владельца — `portfolio.py trade X buy|sell КОЛ-ВО [ЦЕНА]`. Неоднозначные тикеры (обычка/преф) уточни.
   Сектор и целевая доля — `portfolio.py update X --sector … --target 10`.
3. Бумаги, которые комитет ещё не разбирал, ставь в очередь первичного разбора (процедура 4). Если бумаг много,
   разбирай по 1–2 за раз, начиная с самой крупной доли, и скажи владельцу порядок.
4. Покажи `portfolio.py list`, предложи расписание брифингов (раздел «Расписание»), если его ещё нет.

### 2. Ежедневный брифинг («что с портфелем», плановый запуск после закрытия)
Строго по `references/family-office.md`, раздел «Ежедневный брифинг»:
`portfolio.py session --save` → `news.py <тикеры портфеля> --days 3` и проверка ⚑ по первоисточнику →
объяснение каждого сигнала (почему двигалась бумага) → сверка с `thesis.md` → риск → календарь на 14 дней →
вопрос адвоката дьявола → эскалация в комитет по правилам → брифинг в `_portfolio/briefs/<дата сессии>.md`
(шаблон «Ежедневный брифинг» в `report-template.md`) → новое знание о бумагах (объяснённые движения, подтверждённые
события) — строкой `wiki.py log "…" --entity X --source "…"`, без количеств и сумм позиции → `wiki.py sync` →
короткое сообщение владельцу (шаблон там же).

### 3. Недельный обзор
По `family-office.md`, раздел «Недельный обзор»: `portfolio.py review --save`, новости за неделю (`news.py <тикеры> --days 7 --all`),
атрибуция, здоровье тезисов и очередь комитетов, риск и баланс, календарь на 2 недели → `_portfolio/reviews/<дата>.md` (шаблон «Недельный обзор»).
Вместе с обзором: `wiki.py lint --save` (исправь битые ссылки, цифры без источника, противоречия) и `wiki.py digest` — допиши «Выводы недели».

### 4. Инвесткомитет по бумаге (первичный разбор, эскалация, «стоит ли докупать X»)
0. **Сначала вики:** хаб `<ТИКЕР>/<ТИКЕР>.md`, по ссылкам — тезис, последний протокол, конспекты отчётов;
   `wiki.py find "<тикер или тема>"` — что уже известно (в общем хранилище — и от агента акций).
1. **Сбор в папку бумаги** (параллельно, где можно):
   - `moex_share.py X --save` — рынок и дивиденды; `news.py X --days 90 --all` — фон новостей, ⚑ открой и проверь.
   - Последняя отчётность МСФО и презентация (сайт компании → «Инвесторам», e-disclosure.ru по ИНН) →
     `report_extract.py <URL> --save X --name <год-период-тип>`; прочитай ключевые разделы (`reading-reports.md`).
   - `gir_bo.py <ИНН> --save X` — РСБУ (если дивиденды считаются от РСБУ или это холдинг).
   - Ключевая ставка, ОФЗ, отраслевые драйверы; корпоративные события (дивполитика, СД, ГОСА, байбэк, допэмиссии, санкции, суды).
2. **Факты:** конспект в заметке каждого нового отчёта `reports/<имя>.md` (цифры со «стр. N»), `financials/ifrs.md` и профиль `README.md` бумаги.
3. **Оценка:** `valuation.py` — мультипликаторы против истории и 3–5 аналогов, DCF/дивмодель, обратный DCF.
4. **Заседание** строго по `expert-panel.md`: независимые мнения → атака адвоката дьявола → ответы → голосование →
   решение председателя. Где есть субагенты (Claude Code — Agent/Task, Hermes — делегирование), запускай экспертов
   параллельно и независимо; иначе играй роли последовательно, не подглядывая в выводы следующих.
   Комитет для бумаги из портфеля дополнительно отвечает: держать ли текущую долю, какой максимум доли, что делать
   при движении цены на ±15%.
5. **Сохранение:** протокол — `analyses/<YYYY-MM-DD>-committee.md` (шаблон «Протокол инвесткомитета»); `thesis.md` (тезис, антитезис,
   диапазон стоимости, триггеры пересмотра, что проверить в следующем отчёте); `desk.py analysed X --verdict "…" --score N --target ₽`.
6. **Вики:** главные факты и выводы — `wiki.py log "…" --entity X --kind факт|вывод --source "…"`; сквозное — в `topics/`.
   Решение владельца по позиции с аргументами — `wiki.py note decision "…" --entity X` (без количеств и сумм).
7. **Ответ владельцу:** TL;DR решения, голоса, аргументы за/против, оценка, триггеры, путь к протоколу.

Сокращённый вариант — «вышел отчёт / что нового по X»: прочитай тезис, `desk.py status X`, `news.py X`, `moex_share.py X --save`,
архивируй отчёт, сверь с триггерами. Тезис не задет — короткая сводка (шаблон «Сводка по обновлению») и `desk.py log`; задет — полный комитет.

### 5. Бумаги вне портфеля
Можно следить за кандидатами на покупку: `desk.py add X --note "кандидат"`. Они получают папку и комитет, но не входят
в расчёт портфеля. Сравнение кандидатов с позициями — сокращённый комитет по каждому и общий вывод
«что лучше по соотношению качество/цена».

## Правила (обязательные)
- **Не выдумывай цифры.** Каждая цифра — с источником (скрипт / URL / страница отчёта) и датой. Различай МСФО и РСБУ, обычку и преф, LTM и прогноз.
- **Объясняй движение только фактами.** Причина не найдена — так и пиши.
- **Новости и форумы — гипотезы до проверки** первоисточником; статусы ✅/❌/⚠️/💬 по `news-forums.md`.
- **Адвокат дьявола обязателен**: в каждом брифинге — один вопрос, в каждом комитете — полная атака.
- **Пиши в папки.** Брифинг, обзор, протокол, тезис, хронология, конспект, строка в `log.md` — иначе результат потерян.
- **Вики — по правилам `references/wiki.md`**: frontmatter, ссылки `[[ТИКЕР/ТИКЕР|ТИКЕР]]`, у каждой цифры источник, история не переписывается, личные данные — только в `portfolio.json` и `_portfolio/`. Позиции меняются только со слов владельца, через `portfolio.py`.
- Это аналитика, а не индивидуальная инвестиционная рекомендация: варианты, риски и аргументы; решение за владельцем.
  Сделки не исполняешь, доступы к брокерскому счёту не просишь.
- Русский язык, сначала вывод (TL;DR). Суммы — в ₽ с разрядами, доли — в %, ставки — в % годовых.
- При отказе MOEX — повтори, затем возьми данные с сайта биржи или другого источника и отметь это.

## Расписание (cron Hermes / OpenClaw, задачи по расписанию Claude)
Задание должно быть самодостаточным: при запуске по расписанию агент не помнит разговор, поэтому в тексте назови навык и процедуру.
Время московское.
- **Ежедневный брифинг**, будни 19:15: «Используй навык ru-portfolio, процедура 2: ежедневный брифинг семейного офиса по моему портфелю. Сохрани брифинг и пришли короткое сообщение».
- **Недельный обзор**, суббота 10:00: «…процедура 3: недельный обзор портфеля».
- **База знаний**, пятница 18:00: «…`wiki.py lint --save` и `wiki.py digest`: исправь найденное, допиши выводы недели».
- **Дневная проверка** (по желанию), будни 13:00: «…`portfolio.py session --alerts`; пиши, только если есть движение больше 5% или новость ⚑ по бумаге портфеля».

Hermes: `hermes cron create "15 19 * * 1-5" "<текст задания>" --skill ru-portfolio --name "Брифинг портфеля" --timezone Europe/Moscow`
(или попросите в чате «каждый будний день в 19:15 присылай брифинг»). Задания выполняет шлюз: `hermes gateway` должен работать
(`hermes gateway install` ставит его службой).
OpenClaw: `openclaw cron add "15 19 * * 1-5" "<текст задания>" --name "Брифинг портфеля" --tz Europe/Moscow` (нужен запущенный Gateway).
Claude: задача по расписанию в приложении Claude или `/schedule` в Claude Code с тем же текстом.
